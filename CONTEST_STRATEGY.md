# NSRC: постоянные условия основного тура

1. На все 100 задач выделено **100 000 приведённых токенов**. Выходные и
   токены рассуждений учитываются полностью; 10 входных равны одному выходному.
2. Сначала решаем задачи, для которых есть проверяемое локальное решение без
   вызова модели. Остальные ранжируем по ожидаемым баллам на токен:
   `reward × P(успех) / оценка_токенов`.
3. Пропускаем только доказуемо невыполнимые по локальным признакам задачи
   (отсутствующий файл, запись или обязательное поле). Для неоднозначных
   случаев применяем короткий вызов модели, если ожидаемая выгода оправдывает
   расход. Не выдаём догадки за проверенный ответ.
4. Доступны четыре модели: `qwen3.6-35b-a3b`, её `-noreason` вариант,
   `qwen3.8-27b` и её `-noreason` вариант. Начинаем с версии без рассуждений;
   на сложном повторе можем перейти к версии с рассуждениями. Маршрутизация
   зависит от типа задачи и остатка бюджета.
5. Формулировки финальных задач будут новыми, но похожими на выданные примеры.
   Правила для конкретных шаблонов должны иметь безопасный переход к общему
   решателю. Поле `expected` примеров не читается рабочим харнессом.
6. После каждого вызова сохраняем фактический расход и уточняем оценки для
   следующих задач. Ответ сохраняем сразу. При приближении к бюджету оставляем
   запас, чтобы не потерять уже полученные баллы.

Оценки сейчас эвристические: организаторы не дали размеченных траекторий.
Их нужно калибровать на собственных запусках, проверяя долю решённых задач и
ошибку прогноза токенов по каждому типу и модели.

Первый контрольный набор и фактические расходы записаны в `CALIBRATION.md`.
Он маленький и синтетический; оценки обновляются во время настоящего прогона.
