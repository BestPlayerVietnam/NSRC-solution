# Парное сравнение production-харнесса, 12 ноября 2026

Зафиксированы два Docker-образа, runner и 24 новых синтетических задания до обращения к API. По шесть задач на математику, код, CSV и поиск: пять выполнимых и одна с недостаточными данными или противоречием. Награды 1–3 назначены независимо от сложности. Обе версии получают одинаковые задачи; эталоны и hidden tests недоступны решателю.

Правки кода дополнительно проверены тестами, которых не было в solver workspace. Численные ответы сверяются с эталоном; поисковые — с точной строкой. Все пять выполнимых задач каждого домена пройдены кандидатом. Это целевая проверка известных структурных слабостей, а не случайная репрезентативная выборка финала. Одновременно менялись инструменты и первая модель; разложить прирост по компонентам этот эксперимент не позволяет.

## Что пока не улучшилось доказательно

Новый solver решает больше задач, но расходует больше. Одна противоречивая задача на код потребовала двух запросов и 998,8 токена (36,5% расхода кандидата), прежде чем он отказался. Предварительный прогноз был 96,0. Более осторожная проверка невозможности не объявляет задачу нерешаемой только по привычному шаблону; цена этой осторожности заметна.

На задачах с хотя бы одним API-вызовом MAE предварительного прогноза составил 13,98 у старой версии (12 задач) и 102,14 у новой (19 задач). Это разные множества попыток и разные execution policies; эти числа не являются чистым сравнением двух оценщиков. Они показывают, что точность нового предиктора ещё нельзя считать подтверждённой. Для кандидата MAE по доменам: math 22,28 (n=5), code 254,02 (n=6), CSV 14,70 (n=4), search 61,58 (n=4).

Рабочий оценщик остаётся лёгкой эвристикой с раздельной online-калибровкой по модели, домену и версии маршрута. Ранее обученные ridge/logistic модели не включены: их данные получены на другом solver; на свежем наборе регрессия для reasoning также ухудшала прогноз. Квантильный бустинг — кандидат следующего независимого исследования, а не заявленная реализованная точность.

## Учёт и ресурсные ограничения

Оба процесса завершились кодом 0. Все 32 физических вызова имеют полный согласованный usage; reasoning уже включён в output и посчитан один раз. Ошибок, превышений резервов и отказов бюджета нет. Дельта общего журнала 3 200,6 точно равна 465,4 + 2 735,2. Два неизвестных расхода старого исследования остаются зарезервированными; их не возвращали.

| Модель | Учтено за все эксперименты | Остаток из 100 000 | В этом сравнении |
| --- | ---: | ---: | ---: |
| `qwen3.6-35b-a3b-noreason` | 18893.4 | 81106.6 | 311.1 |
| `qwen3.8-27b-noreason` | 18676.6 | 81323.4 | 2015.6 |
| `qwen3.6-35b-a3b` | 97998.9 | 2001.1 | 0.0 |
| `qwen3.8-27b` | 62354.3 | 37645.7 | 873.9 |

Qwen 3.6 reasoning в этом сравнении не вызывается из-за остатка 2 001,1; все четыре модели участвовали в предыдущем исследовании. Эти лимиты разработки не меняют конкурсные 100 000 токенов на весь набор.

Финальный образ `nsrc-harness:latest` — **644MB** по конкурсной команде `docker images --format`, 97 runtime-дистрибутивов. Ограничения запуска: 8 CPU, 16 ГБ RAM, read-only root, tmpfs, без локальных нейросетевых весов. Шесть рабочих Python-модулей побайтно совпадают с образом. Размер прежнего образа — 1.42GB; старое значение около 309MB измерялось другим способом.

Установка runtime wheels заняла 641,7 с, экспорт образа — 16,1 с при уже загруженных base/uv слоях. Это укладывается в 1000 с для измеренной сборки; полностью холодную загрузку registry и чужую сеть этот замер не гарантирует.

Проверки финального образа: 78 unit/regression тестов в Linux; 8/8 примеров организаторов; реальный openJiuwen-клиент против локального fake API. Отдельно прошли две проверки relay без платных вызовов. Текущий образ не содержит экспериментов, датасетов и ключей.
